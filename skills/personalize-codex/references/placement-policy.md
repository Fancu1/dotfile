# 偏好落点策略

## 分类矩阵

| 候选内容 | 正确落点 | 判断条件 |
|---|---|---|
| 全局协作规则 | `~/.codex/AGENTS.md` | 跨多个项目长期适用，稳定、简短、可执行 |
| 项目规则 | 项目 `AGENTS.md` 或更具体的嵌套文件 | 只与该仓库、模块、命令、环境或业务事实有关 |
| 场景流程 | 对应 Skill | 有清晰触发场景，需要步骤、判断标准、产物或工具约束 |
| 滚动认知 | Skill 状态目录 | 会变化、依赖证据、需要进度或历史、不能当硬规则 |
| 平台内部记忆 | 不作为执行事实源 | 不保证自动加载或当前可信，不承载必须执行的规则 |
| 一次性选择 | 不持久化 | 只服务当前任务，没有明确长期复用价值 |
| 敏感或推测信息 | 不持久化 | 涉及高敏感信息，或不是用户明确表达的事实 |

## 判断顺序

1. 这是一条必须长期执行的规则，还是会变化的认知？
2. 它适用于所有项目、一个项目，还是一个可识别场景？
3. 当前是否已有同义或更高优先级规则？
4. 能否写成短小、正向、可观察的行为？
5. 写入后是否会扩大授权、产生副作用或与安全边界冲突？

优先使用最窄且足够的作用域。项目规则不得提升为全局习惯；场景流程不得塞进 `AGENTS.md`；不可信结论不得升级为强制规则。

## 需要直接更新的表达

用户明确使用“记住”“固化”“以后都这样”“写进 AGENTS/Skill”“撤销/忘记这条规则”等表达时，属于偏好变更授权。仍需遵守准确目标、冲突与高影响门槛。

普通的“我这次想用 X”“这个回答短一点”“这个方案没问题”不是长期授权，除非用户明确说明以后适用。

## 高价值提醒

未明确要求固化时，仅在至少满足一项时提醒：

- 同一偏好在不同任务中重复出现。
- 它能避免明显的反复解释或操作摩擦。
- 它是跨项目稳定原则，而不是当前选择。

提醒只包含候选规则、推荐落点和一个是否固化的问题。一次对话中同一偏好最多提醒一次；用户拒绝后不在当前上下文重复建议。

## 典型示例

- “以后个人工作流都不要让我选模式” → 全局 `AGENTS.md`。
- “这个仓库测试统一用 `make verify`” → 项目 `AGENTS.md`。
- “代码健康检查每次同时考虑变化、未覆盖模块和全局问题” → `$codebase-health`。
- “当前产品下一方向可能是改进 onboarding” → `$product-direction` 状态，不能写成全局规则。
- “这次实现用 Postgres” → 当前需求决定或项目文档，不提升为个人全局偏好。
