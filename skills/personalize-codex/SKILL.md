# Personalize Codex

让用户只表达希望长期保留的习惯，由 AI 判断正确落点并完成最小、安全、可审计的更新。不要把所有偏好都堆进全局 `AGENTS.md`。

## 1. 识别意图与授权

1. 读取当前全局和适用项目的 `AGENTS.md` / `AGENTS.override.md`、相关 Skill、工作区状态与已有个性化决策索引。
2. 用户只讨论偏好治理、表达一次性选择或尚未要求固化时保持只读。
3. 用户明确说“记住”“固化”“以后都这样”或明确要求撤销时，视为授权进行范围内的本地偏好更新与状态记录。
4. 目标唯一、影响局部且无冲突时直接更新；有多个合理落点、冲突、授权边界变化、批量删除或较大全局影响时先给出提案并询问。
5. 批量整理全局规则始终先提案，不因用户使用“整理”一词直接大规模重写。
6. 推送、提交、远程修改、删除重要资料和任何超出偏好固化范围的动作仍需单独授权。

## 2. 使用自然语言单入口

不要要求用户选择 action、目标文件或偏好 ID。先从表达中提取：期望行为、适用场景、适用范围、例外和是否是明确授权；再按 [references/placement-policy.md](references/placement-policy.md) 选择落点。

默认选择：

- 跨项目稳定协作规则 → 全局 `AGENTS.md`。
- 单仓库事实、命令和边界 → 项目 `AGENTS.md`。
- 特定场景的流程、判断标准和产物 → 现有或新的 Skill。
- 会变化、带证据时效或置信度不足的信息 → 对应 Skill 的状态。
- 单次选择、模糊推测和敏感信息 → 不持久化。

实际目标文件是执行事实源；个性化状态只是索引和决策历史。

## 3. 检查重复、冲突与价值

1. 搜索同义规则、较高优先级规则、项目覆盖项和相关 Skill，避免重复表达。
2. 区分补充、收窄、替换和冲突。不能通过增加另一条模糊规则掩盖冲突。
3. 将偏好改写为简短、可执行、适用范围清楚的正向规则，不记录整段对话或推测出的动机。
4. 用户没有明确要求固化时，只对跨任务价值高、重复出现或能避免明显摩擦的偏好简短询问一次；不创建候选文件、不自动写入。
5. 不从行为推断敏感身份、健康、财务、凭证、私密关系或其他高敏感个人信息。

## 4. 执行最小更新

1. 增量修改准确位置，保留已有用户改动，不重排或重写无关内容。
2. 修改 Skill 时先完整读取 `$skill-creator`，保持自然语言单入口，并运行其校验；新 Skill 只有在形成独立、重复、分步骤场景时才创建。
3. 修改 `AGENTS.md` 时只写稳定、短小、跨任务可执行的规则；背景、证据和变化历史写入决策记录。
4. 写入会变化的状态时标注来源、置信度、观察时间和重新验证条件，不能提升为硬规则。
5. 先成功修改事实源并验证，再按 [references/state-schema.md](references/state-schema.md) 追加决策记录与更新索引。事实源失败时不得记录为已生效。

具体冲突处理、撤销和验证见 [references/change-and-validation.md](references/change-and-validation.md)。

## 5. 撤销与替换

用户明确要求忘记或撤销时，先定位实际生效规则及其覆盖关系：

- 唯一且准确匹配时删除或替换该规则，并将原决策标记 `superseded`。
- 多处生效、会扩大权限或删除一组规则时先列出影响并询问。
- 不通过删除整个章节、文件或状态目录来处理一条偏好。
- 撤销后验证更高或更低层规则不会让同一行为继续意外生效。

## 6. 完成判定

仅在以下条件满足时结束：偏好与作用域已明确；落点符合分类规则；重复、冲突、优先级和敏感性已检查；修改保持最小；事实源和相关 Skill 已验证；决策索引与历史一致；未授权动作未执行；用户收到新规则、落点、影响与撤销方式的简短说明。
