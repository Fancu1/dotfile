# repo-init-rule

产出**不是一份文档，是一条能跑通的验证回路** —— CLAUDE.md 只是记录跑通结果的
副产品。写一条没跑过的命令比不写更糟：后面的流程会照着它跑。

## 铁律

1. **不许写任何没在本次跑过的命令。** 每条都要有本次的输出和 exit code
2. **不许写形容词。** 「分层清晰」「保持可维护」对模型零约束力，纯占 context
3. **探测出答案的不做成题。** 包括读全局 CLAUDE.md —— 那里定过的不再问一遍
4. **问不出来的不继续问**，降级成待定注释（见第 4 步）

## 第 1 步 · 探测

有什么读什么，**读不到本身就是信息**：

- `~/.claude/CLAUDE.md` —— 全局已定的，这里一律不重复
- 本仓库 `CLAUDE.md` / `.claude/CLAUDE.md` / `CLAUDE.local.md`
- 依赖清单（`pyproject.toml` / `go.mod` / `package.json` …）、`README`
- `git log --oneline -30` —— commit 规范从这里推断，**不问**
- 源码目录：有没有代码、怎么组织的

**空目录也是探测结果，不是失败。**

探完定模式：没有 CLAUDE.md → **建立**（第 2–4 步）；已有 → **更新**（第 5 步）。

## 第 2 步 · 依赖图决定问什么

**上游未定 → 下游不问。** 这是防止问出一堆用户答不上来的题的唯一机制。

| 上游 | 定了才能问的下游 |
|---|---|
| 语言 / 运行时 | 测试框架、lint 规则、包管理、目录布局 |
| 有没有代码 | 架构类的东西是**事实**还是**意图** |
| 有没有 git 历史 | commit 规范（有历史就推断，不问） |
| 单人 / 多人 | 分支、PR、review 流程 |

题库**只写题目，选项现场生成** —— 默认项取探测到的现状，没有现状取生态默认：

**L0 底座**（永远能问）
- 故意排除：不用什么、不做什么
- 功能开发走不走 `/dev-workflow`

**L1**（语言定了才问）
- 测试框架 + 测试放哪
- lint / format 工具，重点问**跟默认不同的那几条**
- 类型检查严格度
- 包管理 / 怎么跑起来

**L2**（有代码才问，空项目**全部**降级成待定注释）
- 错误处理风格
- 分层禁令
- 日志 / 配置约定

### 提问的质量线

用 AskUserQuestion，**最多 2 轮、每轮 ≤ 4 题**。

- 每个问题必须**指向 CLAUDE.md 里的一行**。答完不知道往哪写 = 这题不该问
- 每个选项带一句「它意味着什么」，推荐项放第一个
- 默认项来自探测结果或生态默认，不是你拍脑袋
- 2 轮问不出来的 → **停止追问**，写成待定注释

## 第 3 步 · 立回路（建立模式）

**在写任何 CLAUDE.md 之前**：

1. 装最小可跑骨架：一个包结构、**一个真的会跑的测试**、lint 配置
2. 当场跑三条，逐条贴命令 + 输出 + exit code：测试 / lint 或 typecheck /
   能构建或能启动

没有那个测试，直接跑 `pytest` 会 exit 5（no tests collected）—— 那验证的是
「命令存在」，不是「回路通」。

**没有 build 概念的（Python 等），第三条映射成能 import 或能启动**
（`python -c "import pkg"` / `uv run app --help`），不要硬造一个 build 命令。

## 第 4 步 · 写 CLAUDE.md

### 准入：两问都答「否」才写

1. Claude 读代码能不能自己知道？能 → 不写
2. 这条写死后，改代码时会不会跟着变？会 → 不写

留下的交集是**推不出来 + 不跟代码一起变**。过期的指令比没有更糟 —— 模型会
自信地照做。

| 内容 | 去哪 |
|---|---|
| 命令、环境怪癖 | CLAUDE.md |
| 跟工具默认**不同**的约定、故意排除的做法及理由 | CLAUDE.md |
| 目录结构、模块清单、依赖列表、当前进度 | **哪都不写**，让它自己去读 |
| 必须强制的（提交前必跑 lint） | hook —— 本 skill 不生成，告诉用户有这条路 |

### 架构类写成禁令，不写愿景

- ❌ 「保持分层清晰」 → 无法检验
- ✅ 「HTTP handler 不许直接碰数据库，走 service 层」
- ✅ 「不引入 ORM，手写 SQL」 —— 是决策，读代码只看得到结果、看不到理由

### 待定项用 HTML 注释

块级 HTML 注释在注入 context 前会被剥离 —— 人看得见、模型看不见、零 token。
定不了的留在原地，下次更新模式来捡：

```markdown
## 错误处理
<!-- 待定：等第一个 handler 写完再定 —— wrap 还是 sentinel error -->
```

### 长度

**目标 ≤ 200 行**（官方线，超了降低 adherence）。还要多守一层：项目 CLAUDE.md
会加载进**每一个 subagent**，并行 3 个就是 3 份，长度成本乘以并发数。

内置 `Explore` 和 `Plan` **不加载 CLAUDE.md**，且没有配置能改。要它们守的规矩
只能在派活的 prompt 里重述，别指望写进 CLAUDE.md 能管到它们。

## 第 5 步 · 更新模式

已有 CLAUDE.md 的病通常是**过期和膨胀，不是缺内容**。默认只做三件事：

1. **验** —— 里面每条命令当场跑一遍。这是唯一能机械发现过期的手段，必出结果
2. **删** —— 拿两问过一遍。能推出来的、已跟代码不一致的、形容词，删
3. **捡** —— HTML 注释里的待定项，看现在能不能定；能定就问，问完转正

**加**只在用户明说方向时做，不要每次把所有维度重问一遍 —— 那样跑三次你就不用了。

改完**把删掉的和改掉的列给用户**，不要静默重写。

## 完成判据

- [ ] CLAUDE.md 里每条命令都有**本次**跑出来的输出和 exit code
- [ ] 测试 / lint / 构建或启动 三条齐全（`/dev-workflow` 阶段 5 硬依赖这三条）
- [ ] 全文没有无法检验的形容词
- [ ] 总行数 ≤ 200
- [ ] 定不了的都进了待定注释，没有硬凑的内容
- [ ] 更新模式：删改清单已给用户过目

任一条不满足 → 补。不要交付一份带空头支票的 CLAUDE.md。
