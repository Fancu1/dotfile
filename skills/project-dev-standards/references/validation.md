# Skill 行为验收

仅在创建、维护或验收本 Skill 时读取。结构校验不能替代行为演练；作者演练、独立 AI 接续和真实项目长期效果分别报告，不互相冒充。

## 方法与隔离

- 在新建临时根中放样例项目、独立规范库及演练证据。显式提供项目根和库根，不写入真实 Scope 或默认个人库。
- 先准备原始场景输入：用户请求、最少代码/配置/现有规范、合法或故意缺失的全局版本。生成任务使用 Skill 指令读取输入后实际创建产物；不能把手写预期答案或生成模板的脚本称为独立 AI 运行。
- 记录输入、执行主体、产生的文件、关键决定及验证命令。重要文件可在前后保存哈希，以检查只读、零变化、保留内容与写入范围。测试输出和日志留在隔离根，不作为日常 Skill 上下文。
- 验证实际规则保护的行为、范围和证据，不以命中固定标题或文字证明语义正确。可用一次性脚本检查引用、清单遗漏、哈希等确定性性质，不建立专用发布/配置系统。
- 不默认启动额外代理。无独立接续执行条件时完成作者演练并明确独立接续未验证；不能把作者再次阅读称为另一 AI 验收。

## 必测场景

| 场景 | 输入要点 | 观察与反例 |
|---|---|---|
| 新建 Go 项目 | 清晰业务目标，独立库有已发布 Go 组合；只提供最少项目事实 | 十领域及其适用问题有结论；版本可读；有推荐而无整张问卷；不发明微服务、数据库或性能承诺。 |
| 已有跨模块读写 | 当前代码存在跨责任写入，既有规则禁止，另有合法的窄只读例外 | 事实、规则、差距及有效例外分开；不把违规扩大成豁免；代码前后相同。 |
| 混合语言 | Go/Python 分别有组合；另设跨语言共享范围存在矛盾的变体 | 文件作用域正确；不同公共版本不直接判错；真实重叠冲突标待决，不拼出未验证的新组合。 |
| 异步 | 明确接受后跨重启保留；实现只有内存队列；存在失败、重复结果的需求 | 记录承诺与实现差距、责任和可观察条件；机制可选，不能宣称已有队列即可靠。 |
| 增量及清单变化 | 已完成规范；补充一个用户问题，再重复相同请求；另修改同编号问题的判断前提 | 只更新受影响部分，保留历史和扩展；重复请求内容与依据不变时零写入；同编号语义变化不能沿用旧完成状态。 |
| 硬约束冲突 | 新偏好与有效约束冲突，未明确授权替代；有独立无冲突更新 | 旧约束保留、冲突候选未生效，无冲突部分可继续；不称全部完成。 |
| 缺失引用与版本升级 | 固定旧版本；入口推荐新版本；分别测试旧版本可用与缺失 | 旧版可用就保持；缺失则报告准确缺项；不升级或回退。全局库完全缺失时可完成独立项目内容但不称接入成功。 |
| 只读与保留用户内容 | 请求只检查；生成时又有已有 AGENTS、等价规范或保存前用户修改 | 检查全过程目标目录零写入；生成复用已有事实源并保留内容；保存前发现变化重读合并。 |
| 接续 | 仅提供生成的项目、入口及固定全局文件，不提供原对话或维护过程 | 能找出硬约束、默认、例外、缺失与开放空间，正确判断一个跨模块改动；作者检查可验证产物自足性，独立接续需另记真实执行证据。 |

## 完成报告

运行 `skill-creator/scripts/quick_validate.py` 对当前 Skill 的结构校验，检查 UI 元数据和全部内部引用。结构通过仅证明对应静态性质。

对实际演练逐项记录通过、失败或未执行及原因；发现问题先修正 Skill，再仅重跑受影响场景。不将未运行的示例、预期表或规则检查脚本输出包装成“全部行为测试通过”。最后报告已安装路径、调用方式、验证命令及退出状态、证据位置与剩余限制。
