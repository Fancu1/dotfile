# 项目开发规范

让后续 AI 根据当前项目和简洁规范稳定开发，不需要重读原对话。约束必要的结果、责任和边界；技术栈、运行结构、ORM、队列等分别作为事实、默认选择或有依据的硬约束，不因写入文档就永久锁定。

## 入口与授权

- 用户只需描述场景和目标；自动判断建立、局部更新或只读检查，不要求选择模式、填写清单或记忆编号。
- 讨论、评审和检查只读。明确生成或更新项目规范即授权相应本地规范文件及项目读取入口的必要修改，不逐项请示。若用户限制只出草案或不改入口，遵守限制并说明接入状态。
- 本 Skill 不修改业务代码、全局规范库、其他 Skill、全局 AGENTS 或远程内容，不启动 goal、开发或部署。生成规范不等于授权修复现有违规代码。
- 解析唯一的目标项目根与规范库根；遵守用户指定路径和隔离范围，避免写回当前工作目录或默认个人目录。已有等价规范优先复用，不自动迁移、复制或覆盖。

## 调查与判断

1. 读取有效项目指令和已有规范，按 [完整确认清单](references/checklist.md) 调查。已有项目先核对当前代码、配置、测试及相关历史，再参考文档；按核心流程定向取证，不默认审计整个仓库。区分静态事实、运行证据、推论和未知，不显示凭证。
2. 明确项目阶段、目标、已有能力和真实限制。新项目没有代码时依据用户目标推导推荐职责；没有依据的容量、权限角色、架构和可靠性承诺不能写成事实。影响方向的目标缺失才询问。
3. 沿核心流程检查责任、数据与同步／异步预期，并用相关失败、重复、并发和重启场景寻找矛盾。流程推演不替代全清单。订阅 → 抓取 → 保存文章 → AI 处理 → 展示只是场景示例，不是所有项目或 Scope 的既定契约。
4. 每项形成约束、沿用或采用默认、交给实施决定、不适用之一；说明依据和剩余边界。未处理或实质冲突标为待决，不计完成。一个领域内尚未回答的重要问题不能被领域级“已处理”掩盖。
5. 普通选择自主采用有依据的推荐，集中报告重要决定。只将无法合理判断、影响目标、兼容承诺或硬约束的取舍交给用户，给出推荐和影响。不能通过“交给实施”逃避必要决定；用户认可方向不等于亲自确认每条规则。

## 形成与维护规则

首次生成、接入全局规范或准备写入前，读取 [产物与接入约定](references/output.md)。局部维护也按该文件核对增量失效与保存方式。

- 全局规范固定明确的已发布兼容组合，按语言和代码范围引用并实际读取；已有固定版本不自动升级。库缺失时完成独立可做的项目内容，标明接入未完成，不虚构版本或假装已经读取。
- 正文分开当前事实、硬约束、默认选择、有效例外与开放空间。每条规则说明适用条件、要求、必要原因及可观察的违反方式；不得用“高质量”“合理分层”代替具体边界。相关例外放在能正确理解规则的位置。
- 不自动把旧代码提升为规范或永久豁免，也不因生成规范就声称代码合规。新目标与现状的差距写清范围及后续开发约束；未落实的目标不写成当前事实。
- 不复制全局代码风格和注释正文；项目差异说明范围和理由。数据访问及跨模块约束按项目制定，不上升为全局原则。具体需求方案、测试执行、进度和交接方法留给需求开发流程。
- 更新比较本次请求、项目事实、清单问题及规则前提；只复查受影响项和关联项。保存清单内容快照及用户扩展，不能只比编号。新增问题与修改有效规则分别记录，内容和依据均未变化时不写入。
- 硬约束冲突不能静默放宽，更具体文件不自动获准覆盖。可在旧规则内处理的部分继续；受影响候选保持未生效，指出所需决定。普通实现选择由后续 AI 在目标和规则内自主推进，最终说明重要决定，不必重新运行本 Skill。

## 完成与接续

写后重读实际文件，核对清单结论、规则语义、固定引用及项目入口，确保后续 AI 仅凭规范正文和当前项目即可行动，不必读完整决策历史。只读检查在回复中报告，不为留痕写入文件。

交付简述实际产物、覆盖范围、重要自主决定、待决或未验证项。分别报告清单处理、全局接入、项目读取入口和规范检查结果；有待决不称全面完成。规范完整不证明项目代码合规，结构校验不证明实际行为稳定。

需要把握讨论粒度时读 [交互示例](references/examples.md)。开发或验证本 Skill 时读 [行为验收](references/validation.md)，日常使用不加载测试材料。
