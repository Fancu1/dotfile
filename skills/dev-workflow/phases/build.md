# 阶段 3 · 开发

按 PLAN 的并行分组逐组推进，每个子任务产出代码 + 验证证据 + 一个 commit。

## 谁跑

- **并行组**（组内多个子任务）→ 每个子任务一个 **fresh subagent**，必须
  隔离，否则它们会互相看到对方的中间状态
- **串行的单个子任务** → 主会话直接做。为一个小改动派 subagent 不划算，
  它要重新把代码读一遍

subagent 的输入：**它自己那条子任务** + `.dev/BRIEF.md` + 项目 CLAUDE.md。
不给 `CHALLENGE.md`（方案层面的意见已经吸收进 PLAN 了），不给别的子任务
的内容。

## 铁律

1. **不许改测试断言来让测试通过**。测试失败就改代码，改不动就报告。
   改断言等于把验收标准偷偷放宽 —— 这是最需要防的一种作弊。
2. **不许改 `.dev/BRIEF.md`**。它是锚点。发现 BRIEF 不对，停下来报告，
   由用户决定是否 amend。
3. **不许超出子任务范围**。PLAN 里没声明的文件不要动。发现必须动，
   停下来报告。
4. **subagent 不 commit**，只写代码。commit 由主会话统一做，避免并发写
   git index。

## 流程

按 PLAN 的并行分组，一组一组来：

1. 派活（并行组并发，串行的顺序做）
2. 每个子任务完成后跑**它自己的验证命令**，把命令和实际输出留下
3. 组内全部完成 → 主会话做 **commit 检查 + 提交**
4. 组内**去重扫一眼**：多个子任务有没有各写了一份相同的工具函数？有就
   合并成一处。（PLAN 的「共享新增物拆前置子任务」判据是事前防线，
   这一步是兜底）
5. 进下一组

## commit 规则

主会话在每组结束后，**按 T 序**逐个 commit：

1. `git status` 看实际改动
2. 对照 PLAN 里该子任务声明的「改动文件」
3. **有声明外的文件被改了 → 停下来问用户**。这要么说明 PLAN 不准，要么
   说明 subagent 越界了，两种都不该悄悄提交
4. 一致 → `git add <该子任务的文件>` → commit：
   - **subject 直接照抄子任务标题**，不再判断 type / scope
   - body 写这个改动的「为什么」1-3 行，取自子任务的「做什么」和「复用」

### 返修 commit（review / verify 打回来的）

**不要照抄原子任务标题** —— 那会让完成判据里的「没有多余的 commit」永远
不满足，修完了反而推不进去。

- subject 写 `fix(scope): 描述`，scope 沿用原子任务的
- body 第一行写它修的是哪条：`修复 REVIEW B1` / `修复 VERIFY 第 2 条`
- LOG 里这条标 `R{轮次}`，指到 finding 编号

## 验证失败怎么办

- subagent 自己修，**最多 3 次**
- 3 次还不过 → 停下来，把最后一次的完整报错写进 `.dev/LOG.md` 并报告用户
- **不许**为了让验证通过而放宽验证命令本身

## 完成判据

- [ ] PLAN 里每个子任务都完成且验证通过
- [ ] 每个子任务**至少**一个 commit：首轮那个 subject 与子任务标题一致、
      没有遗漏；返修 commit 走 `fix(scope):`，不算「多余」
- [ ] 每个子任务在 `.dev/LOG.md` 留了一行（fail 的才带完整输出）
- [ ] 没有声明外的文件被改动（或改动已经过用户确认）
- [ ] 测试断言没有被改（如果改了，必须在 LOG 里写明原因并经用户同意）

## LOG.md 模板

**只由主会话写**，在该组 commit 完成后按 T 序追加（这时才拿得到 hash，
也不会出现并行组同时写同一个文件）。**只追加不改写。**

LOG 是**失败档案**，不是验证流水账 —— 成功路径的证据在阶段 5 会被独立
重跑，那份才进 PR。所以成功的只留一行，失败的才值得占地方：

````markdown
- T1 · `pytest tests/test_a.py` · pass · `a1b2c3d`
- T3 · `pytest tests/test_c.py` · pass · `e4f5a6b`
- R1 · 修复 REVIEW B1 · `pytest tests/test_a.py` · pass · `c7d8e9f`
- T5 · `pytest tests/test_e.py` · **fail** · 无 commit
  ```
  <完整报错，含 exit code>
  ```
````

subagent 不写 LOG，它在返回消息里原样带回**验证命令 + 完整输出 + exit
code**，由主会话决定留一行还是留全文。
