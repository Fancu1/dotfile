# 交接卡与过程产物

## 阶段交接卡

在需要用户批准、跨会话恢复或大型需求批次切换时使用：

```markdown
阶段交接
- 当前结论：<已经确认的事实与阶段状态>
- 已做决策：<方案及关键理由>
- 未知与风险：<仍需验证或可能失败的部分>
- 推荐下一步：<为什么现在做它>
- 下一动作：<将修改/执行什么，是否有副作用>
- 需要你决定：<没有则写“无”>
```

不要只让用户回复一个模糊口令。明确说明下一步具体会发生什么，以及批准的范围。

## 最终交付卡

按需求规模压缩或展开以下信息：

```markdown
交付结果
- 结果：<用户可见行为与完成状态>
- 实现链路：<入口 → 核心逻辑 → 输出/消费者>
- 文件职责：<关键文件分别承担什么>
- 关键决策：<选择与取舍>
- 计划偏差：<无，或偏差及原因>
- 验证证据：<命令/场景、结果、退出状态>
- 未验证项：<没有则省略>
- 残余风险：<没有则写“未发现已知残余风险”>
- 建议阅读顺序：<仅在中大型改动中提供>
- 后续操作：<需要用户明确授权的提交、部署等>
```

## 产物策略

- Small：不创建流程产物。
- Medium：优先使用任务内计划；仅在跨会话且确有必要时创建 `.agent-work/current-plan.md`。
- Large：Gate 1 批准后，可创建 `.dev/STATE.md`、`BRIEF.md`、`PLAN.md`、`DECISIONS.md`。
- Challenge 与 Review 默认保留在任务上下文中；只有跨会话确需恢复时才持久化。
- 长期有效的事实应进入测试、代码注释、ADR、项目文档或 PR 描述，而不是永远留在临时状态文件。
- 不擅自删除用户已有的流程产物。由本任务新建的临时文件在结束时说明用途并征求清理或保留意见。

## Large 最小格式

`STATE.md` 记录：需求、等级、当前阶段、已完成、下一步、阻塞、待决项、最后验证和更新时间。

`BRIEF.md` 记录：背景、目标、非目标、不变量、验收标准、范围与关键未知项。

`PLAN.md` 记录：目标方案、迁移/兼容/回滚、实施批次、触达路径、每批验证门和发布前置条件。

`DECISIONS.md` 按条记录：日期、决策、背景、备选方案、理由、影响和重新评估条件。

更新状态文件时保持简短，替换过期状态而不是无限追加日志；决策记录除非明确纠错，否则保持可追溯。
