# 影响面地图

影响面地图用于避免“只找到入口，没有找到完整行为链”。根据等级控制深度，不要求把无关检查写成长文。

## 深度

- Small：在内部快速确认入口、直接调用链、测试面和用户未提交修改；对用户最多呈现 3 个要点。
- Medium：在方案中给出完整但紧凑的影响面摘要。
- Large：把基线、契约、迁移、兼容、发布和回滚纳入正式方案。

## 检查顺序

1. 定位入口与当前行为：用户入口、命令、路由、事件、接口或定时任务。
2. 追踪行为链：调用链、数据流、状态变化、异步边界和错误传播。
3. 查找生产者与消费者：直接调用方、复用方、下游服务、缓存、队列和持久化层。
4. 核对契约：API、类型、Schema、配置、权限、国际化、兼容性和默认值。
5. 核对失败语义：异常、重试、超时、并发、幂等、部分成功和恢复路径。
6. 核对保障面：单元/集成/E2E 测试、日志、指标、告警、文档、CI、构建、发布和回滚。
7. 核对工作区：适用指令、已有未提交修改、可能冲突的触达文件和可用验证命令。

使用代码搜索确认符号引用、配置键、相似实现和测试夹具。不要仅凭目录名或记忆推断影响范围。

## 输出格式

按需压缩为：

```markdown
影响面
- 当前链路：<入口 → 核心逻辑 → 消费者/结果>
- 预计触达：<模块或文件职责，不只列文件名>
- 契约与数据：<变更或不变项>
- 风险与未知：<失败路径、兼容、权限、并发等>
- 验证面：<聚焦、相邻、完整检查>
```

未确认的内容明确标为未知，不把推断写成事实。
