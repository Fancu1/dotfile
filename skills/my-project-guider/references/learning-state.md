## 怎样确认项目身份

先读索引，再解析当前目标的规范化源路径、可安全获取的仓库来源和当前版本。远端地址必须去除账号、口令、查询串等凭据信息后才可记录；不直接输出原始远端配置。不能确认安全来源时，仅记录本地路径。

同一源路径可匹配已有项目。同一仓库的另一个检出只有在来源和项目范围吻合时复用学习记录，同时保留各检出和版本的区别；不要自动把不同分叉合并。只有项目名相同不能复用。新项目使用可读的项目名作为 key；冲突时追加 `-2`、`-3` 等空闲后缀，并在索引中保存真实身份。用户不需要记住或手填这些 key。

无 Git 项目记录真实路径及所核对材料的日期或文件特征，不捏造提交号。来源不可访问时保留学习进度，把事实标为待复核；可继续解释明确标注的一般概念，不能声称已经核实具体实现。

## 记录什么

### 个人背景

保存用户明确表达的目标、偏好和有具体证据的知识背景，注明来自何时的用户表达或参考资料。一次局部理解不升级成全局能力判断。临时的“今天想简短一点”和项目特定的“先跳过 Connector”不变成永久偏好。

### 项目进度

保留项目身份、当前学习目标、更新时间，并用自然语言记下：

- 已讨论的流程、模块和概念，以及用户怎样表现出理解；
- 尚未建立的连接、还未接触的重要视角；
- 具体误解和已经更正的解释，保留造成误解的上下文；
- 当前未解决问题、被插问打断的主线；
- 用户明确跳过的部分及仍需保留的边界；
- 下一次优先切入什么、为什么值得接着学。

“讲过”“用户表示认可”“准确复述”“能够迁移判断”不是强制打分等级。按实际证据描述，允许不确定；不能因为一次“OK”宣布掌握，也不能以反复提问断言基础薄弱。若助手早先把顺序或概念讲错，应记为解释修正，而不是用户缺陷。

没有进展或没有回复不等于放弃。不因最近的问题集中在一个模块，就把其余学习目标丢弃。用简洁状态接续，不让用户管理内部字段。

### 项目事实与证据

每项重要结论记录：具体命题、证据类别、已读的位置或材料、核对日期和版本、适用路径及未核对边界。只保存理解所需的定位与摘要，不复制大段源码或敏感内容。

类别含义：

- 当前实现：本次实际核对的代码、配置、测试定义等；说明静态观察，不等同实际运行验证。
- 文档意图：作者材料明确给出的原因，保留出处。
- 架构推断：根据约束和职责推导的解释，不伪装成作者原意。
- 教学示意：帮助理解的假设场景，不写成真实历史。
- 待复核/未知：旧对话、旧课程或不足的证据，只作为下次调查线索。

“读取了测试源码”“运行了测试”“实际运行系统”分别记录。核对了 HEAD 不等于核对了全部实现；工作区还有修改时，提交号不能完整代表所读内容，记录相关差异。版本没变也不能忽略工作区变化。

新结论替换旧结论时，保留简短更正说明和影响范围，进度与证据相互一致，避免下次又使用旧说法。源码位置和证据链接主要留在这里，不默认加入用户的概念解释。

## 什么时候保存

有重要理解变化、事实更正、学习方向变化或主题收束时，在当前对话内增量保存，不依赖自动化或以后醒来。先完成足够解释，避免记录操作淹没对话；不必每轮或每段更新。没有实质变化不改时间戳。

写入前重读会修改的记录，合并新增事实，不覆盖其他对话或用户刚补充的内容。文件意外格式、冲突或来源不明时保留原文，只在安全的位置补充；无法安全处理就说明未保存，不强行重建。

先保存项目内容，再更新索引。某次写入中断后，下次检查已有目录与身份再补齐，不覆盖已有记录、不产生同项目的第二份档案。找不到索引时可以只读检查已有项目记录，不能因索引缺失就判定没有学过。

记录位置不可写时，说明“本次续学记录未保存”，继续对话；不擅自切换到目标源码目录、另一套记忆或外部服务。不要为了验证不可写而修改真实目录权限。

## 续学与初始资料的处理

先识别项目，再读相关进度和证据，检查本轮要依赖的事实是否需要更新。仓库变化只使相应事实失效，不自动清空用户学过的概念。旧课程不证明当前实现，也不证明用户读过。

本 Skill 初始化时已有的 Tower 记录来自本次教学对话；历史结论均为待复核线索，不是安装时重新验证的实现保证。允许记录“这个主题已讨论”，不允许以相同提交号推定后续结论全部可靠。
