# 验收、交接与自主开发接续

设计正确、文档完整、用户理解、代码完成和运行验证分别成立；本文件定义证明与接手方式，不启动执行编排。

## 1. 从要求追溯到证据

每个核心要求关联设计与至少一种有意义的证明方法。用稳定的需求/场景标识或清晰链接，编号仅方便内部追溯，不要求用户记忆。

| 信息 | 最低要求 |
|---|---|
| 场景 | 证明哪个行为、不变量或明确约束 |
| 前置 | 数据、配置、环境、初始状态 |
| 操作 | 可执行的具体步骤 |
| 预期 | 可观察结果；必要的次数、时间和状态条件 |
| 证明方式 | 针对性测试、集成、运行、命令或人工判断 |
| 对应设计 | 要求、模块、契约、决定或固定示例 |
| 实际结果 | 实施后记录证据、结果、退出状态及未验证原因 |

预期应来自有效需求和规范，不能从实现反推一个容易通过的答案。未运行即未运行，有待定内容的验收项不可标通过。

## 2. 选择与变化相称的验证

完整考虑正常路径、相关失败分支、身份权限与归属、重复并发、事务和状态不变量、异步生命周期、已有行为回归及必要迁移恢复；据实际风险和可观察结果选择，不强制所有项目建设全套系统。

- 小型可逆改动可用针对性验证，不为证明内部函数形状写镜像测试。
- 关键不变量需覆盖真正会破坏它的条件，不只给成功样例。
- 重构/替换可用固定数据新旧对比；明确必须保持与允许改变的行为，旧缺陷不自动正确。
- 涉及数据库事务用实际相应数据库/适配路径的集成证据；SQLite 单测不证明 PostgreSQL 事务。
- 要求进程中断恢复时，使用相关崩溃边界和真实进程中断；普通函数返回错误不能完整替代。
- 外部调用成功而本地保存未提交的窗口，与普通可分类失败分别验证。
- 用户可见链路需相应实际操作证据，构建、健康接口或局部函数测试不能替代。
- 迁移按实际阶段与保留范围设计，不默认线上窗口、无停顿、双队列或在线回退；未上线不等于可清数据。
- 敏感数据使用安全替代或隔离数据，外部操作仍需相应授权。

命令从项目中核实，缺少测试入口可在实施计划中具体安排，不能假装已经存在或运行。区分静态检查、针对性测试、集成测试、构建、真实运行及人工判断。另一 AI 认可、测试全绿都不是全部语义正确的保证。

## 3. 固定示例的验证

计数案例仅适用已确认该行为的需求：每日上限 8、已占 7，新逻辑任务获准后 8；重试仍 8；最终失败仍 8。分别断言三个状态，不能仅查成功后计数。总任务尝试与实际外部调用次数分开观察；允许重复调用不等于允许重复业务写入或重复占额。

哪些数字/条件是固定、哪些是示意必须在规格明确。具体重试次数、跨日规则、错误分类未定时，提出方案或标待决，不利用示例推导未确认决定。

## 4. 交接就绪检查

只依需求入口、明确引用的规范、必要项目代码/配置/运行资料，检查：
1. 能否找到所需规则、版本、代码入口、环境和数据条件？
2. 能否还原正常链路、相关失败链路、异步终态和用户/维护者反馈？
3. 每项确认要求有无设计与验收，是否保留回归行为？
4. 接口、数据、状态、示例、任务、模块文档是否一致？
5. 实施者是否还需重新选择业务行为、责任或重要契约？
6. 能否区分事实、推断、设计、来源、强度、默认和未知？
7. 关键理由、否决原因、替代关系和固定例子是否仍有效且可还原？
8. 尚需讲解什么，用户是否明确选择继续或跳过？
9. 引用有无缺失、基线有无过期、修订有无未同步？
10. 授权包含什么，接下来实际可做什么？

任一关键契约或上层依据仍未知，不把相应设计标就绪。普通局部自主空间须有边界，不属于关键缺项。设计就绪、讲解进度、文档完整分别报告，用户可明确跳过讲解但不能伪称掌握。

交付可简述入口、有效范围、重要决定、待决、自主范围和接手方式；不能只给文件链接而不说明当前状态。

## 5. 新 AI 的接手契约

将以下含义放入规格接手段或 progress.md：
1. 读取需求入口及明确的必读引用，实际读取对应规范正文。
2. 核对当前代码、配置、工作区未提交变化与设计基线；显著变化复查依赖结论。
3. 读取进度、已执行验证、已知基线失败和重要自主决定；不依赖原聊天/个人记忆。
4. 按依赖推进可运行或可验证的步骤，记录结果和剩余事项。
5. 普通实现分歧在目标、规范、契约和授权内自主选择、验证并继续；写理由、影响和可调整方式。
6. 只在目标/明确契约需要改变、硬约束真实冲突、关键条件缺失或授权不足时提出受影响部分，继续独立工作。
7. 维护实现进度、实际证据及必要设计修订，保留目标和验收标准。
8. 最终集中交代重要自主决定、偏差及可调整方式，用户可据此要求修改。

不要求普通选择重新审批；不因一般不确定性停工。推荐路径允许有依据调整，硬契约不能静默改。若更改路径影响文档、测试、契约消费者或已讲解机制，要同步维护。

不得删有效测试、降低预期、缩范围制造完成；不得把写代码、勾任务、另一 AI 认可当已验证；不得自行提交、部署、创建 goal、会话或定时任务。用户明确要求使用 goal 时由实际执行环境处理，本 Skill 不建调度器或固定模型。

## 6. 验证 Skill 本身

结构检查仅证明结构。语义复核检查规则冲突、缺项、必要理由、案例泄漏和工具/授权边界。真实场景演练观察是否按规范调查、提出有依据的建议、逐链路讲解、同步决定并产出可交接文档；用 [案例与演练](examples.md) 的场景，不要求固定措辞。

给无聊天背景的复核者最小原始资料与输出文档，不附作者预期答案或原始讨论来填空。独立 AI/会话复核仅在环境允许且已有授权时使用；同一 AI 模拟必须标同一 AI 自查，不能冒称独立。复核结果不等同最终代码正确。

只在隔离目录生成演练产物，不修改真实项目、全局规则或运行配置。报告执行过的场景、实际观察、未测部分；不能因清单列出 18 项就声称完成 18 项真实演练。
