# Skill 行为验收

此文用于维护 Skill，不是日常生成规范的前置流程。

## 执行方式

使用隔离测试库，通过当前可用的 AI 执行环境实际加载 SKILL.md 及所需引用，从自然语言请求开始。实现可以单 Agent 完成，验收串行调用独立测试上下文；不得把手工准备的最终结果当成 AI 行为。

可以准备旧库、冲突、用户扩展和失败环境作为前置条件。给执行上下文的材料只有实际请求、技能入口、必要原始文件和允许读写范围，不提供预期答案。保存请求、调用退出状态、最终回答、修改前后文件清单及关键内容。不要将测试产物放进个人默认库或项目。

先拍摄文件内容摘要，演练后检查实际差异；证据目录可以在库外。以意图和行为为验收依据，不用固定句子匹配冒充语义验证。

## 场景

1. 空库生成 Go 规范：公共全量及 Go 补充覆盖、仅启用 Go；普通默认有来源，不固定架构。
2. 少量偏好：能推荐并执行，不索要整张问卷，不将 AI 决定记成用户已确认。
3. 修改注释语言并保留公开接口例外：变化限定于相关规则，例外在正文；旧版本不变。
4. 重复同一请求：正文、入口和记录不发生无意义变化。
5. 新增确认角度和修改同编号含义：新项/失效结论被处理，扩展持久保存，不重问全部。
6. 拆分、合并或依据变化：记录前后关系并重新判断受影响项，编号存在不等于已处理。
7. ORM/技术栈诉求：识别项目归属，不生成全局强制架构或修改项目。
8. 公共变化影响语言：实际复查组合，能兼容则复用旧语言版本，冲突不推荐。
9. 关键理由：仅读正文即可理解必要前提和例外。
10. 待决硬约束冲突：不放宽或声称完整完成；检查请求严格只读。
11. 更新中断：对真实调用使用一次性故障夹具，在入口切换前触发实际写入错误。验证旧入口及文件内容不变、用户扩展保留、候选不生效；解除故障后再次自然语言调用，核对恢复而非自动发布残留。
12. 只读检查：比较整个库的内容摘要和文件清单，确认没有写入。

结构校验单独运行 skill-creator 的 quick_validate.py，并检查内部链接、编号唯一性、模板及界面元数据。结构通过不证明行为正确；一次行为演练通过不保证未来每次生成都正确。

若概要日志没有收录写入事件，只有 AI 最终自述不能证明故障实际命中；用隔离的文件操作见证工具记录真实系统返回及入口前后摘要，或明确该项未验证。见证工具仅服务测试，不成为生产 Skill 的依赖。

若当前环境无法实际调用 Skill，明确报告行为验收尚未完成。若故障注入未命中实际切换点，不能声称验证过中断恢复；记录失败证据，调整夹具后重试。
