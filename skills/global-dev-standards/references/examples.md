# 对话示例

示例体现判断方式，不是固定文案或已经选定的个人规则。

## 首次建立

用户：帮我建立 Go 项目的全局开发规范。

AI：我会检查公共与 Go 确认项。没有明确偏好的部分采用可调整的默认，并说明依据。

行为：处理全部公共与 Go 项；把普通默认作为 AI 决定，生成规范和维护记录。不要先发整张问卷，不生成 Python 文件，不询问所有实现细节。

## 局部调整与重复调用

用户：把新代码注释默认改为中文，外部公开接口继续遵循项目已有英文约定。

行为：只复查注释语言及相关公开契约/Go 说明，正文保留外部接口例外；产生实际有变化的文件版本，检查组合并更新入口。其他内容和旧版本不变。

用户：再按刚才的要求更新一次。

行为：核查当前已满足且依据无变化，说明无需变更，不制造新版本或新记录。

## 项目内容与关键前提

用户：所有项目都用同一个 ORM，这个也写到全局规范里。

AI：这会固定项目的数据访问实现，属于项目约定。全局可保留依赖选择时评估维护成本与收益的要求，具体 ORM 由项目选择。

行为：不擅自修改项目或创建架构标准；用户坚持改变本 Skill 的作用域时明确这是范围变化，不能暗中扩充原清单。

用户：补充输入校验要求，下游按相对路径处理，不能接收任意文件路径。

行为：具体路径契约归项目；全局可表达“进入敏感路径操作前，验证输入满足下游信任前提”。在正文保留原因和适用条件，不强制所有外部输入统一路径校验或万能清洗。

## 同编号含义变化

用户：把后台任务那一项细化，除了退出，还要明确谁观察失败。

行为：比较当前条目内容；若已经覆盖就说明而不改版本。若旧库确实缺失，记录新清单修订与旧内容关系，重查对应结论，不因编号未变沿用旧的完成标记。

## 冲突和检查

用户：检查现在推荐的公共和 Go 规范有没有冲突。

行为：实际读取组合和正文，只读报告。发现公共禁止某行为而 Go 强制该行为，说明冲突和影响，不静默选优先级或改写文件。

用户：更新规范，但这个冲突涉及的硬约束我还没决定怎么改。

行为：冲突部分标待决并保留旧有效组合；不受影响的工作可以完成，不把局部完成说成全部确认。
