# 文件组织与更新

## 当前正文就是依据

默认根为 `~/.config/ai-dev-standards/`，用户可指定其他目录。解析为本环境实际绝对路径，整个调用使用同一根。

```text
ai-dev-standards/
├── common.md
└── languages/
    ├── go.md
    └── python.md
```

只生成需要的语言。首次 Go 请求通常只写 `common.md` 与 `languages/go.md`；后来补 Python 时复用已有公共正文，不再创建另一份公共规则。

不创建 INDEX、版本文件、历史记录、推荐组合或发布台账。一个语言默认一份正文；只有确有阅读负担且存在清楚的条件阅读范围时才考虑拆分，并保留明确入口，不为每个检查项建文件。

已有正文、用户扩展和明确例外是更新依据。正文不要依赖维护历史才能理解。用户明确要求额外保存某项信息时，只保存服务其实际用途的内容，不借机恢复全套台账。

发现旧版结构或其他已有组织时，先识别实际引用和当前有效内容，不自动迁移、删除旧文件或复制一套竞争正文。仅有旧版结构而生成请求没有明确迁移意图时，说明这一实际障碍并集中确认迁移范围；其他不依赖迁移的工作继续。新流程不再要求项目固定版本，但也不能擅自改写现有项目引用。

## 更新原则

- 写入前读取目标文件，针对请求做最小语义修改，不用模板覆盖整份现有规范。
- 明确要求改变一条规则即可更新该规则，不把旧规则视为永远不可改变；请求未解决的其他硬约束冲突必须说明。
- 公共规则变化时，读取已有语言规范中受影响的内容，检查是否仍能同时遵守。需要同步修改时仅改关联部分；无法判断的冲突不要写成已经解决。
- 同一请求已经满足时不写文件，不为时间戳、措辞美化或维护记录制造变化。
- 新增、修改、拆分或合并检查项时，根据当前实际含义检查相关正文，不继承“以前处理过”的假定，也不要求恢复版本和快照系统。
- 若用户有额外检查文件或备注，读取相关内容并保留；不因 Skill 升级覆盖用户扩展。新的全局规则直接进入相应正文，属于项目的要求只在回复中解释归属。
- 正常使用可靠的局部编辑或完整文件替换，写入后重读检查。发现并发修改先重读，不覆盖未知改动。写入失败报告实际已改和未改范围，保留可读内容，不能假称多文件更新具有整体原子性；不为此实现发布系统。

## 项目接入

全局文件集中存放，项目直接引用，不复制到每个项目。首次生成后可在回复中给出以下短示例，路径替换为本次实际根：

```markdown
## 适用的全局开发规范

开始开发前，实际读取并遵守：

- /实际规范根/common.md
- /实际规范根/languages/go.md

这些路径始终引用当前内容，同时遵守本项目规范。
引用无法读取或规则存在冲突时，说明受影响范围，不得默默跳过。
```

项目 AGENTS 应要求读取项目规范，项目规范再要求读取上述公共及本次涉及的语言文件。链接存在不等于内容已经加载。全局更新后，下次读取采用更新后的正文，不需要升级版本或同步副本。

本 Skill 只提供引用说明，不自行写项目或 AGENTS。其他流程仍要求旧版 INDEX/版本组合时，指出接口尚未同步，不创建伪版本迎合，也不擅自修改其他 Skill。
