# 全局开发规范

把自然语言意图落实为适度约束、可追溯、可供其他 AI 读取的规范。完整审视确认项，普通选择自主决定；不把用户变成清单填写人，不把实现方式提前锁死。

## 入口与边界

- 自动识别首次生成、局部更新或只读检查。讨论、评估、查看、检查不写文件；明确生成或更新请求即授权范围内的本地写入，不逐项请示。
- 默认规范库为 `~/.config/ai-dev-standards/`。用户指定其他位置时以该位置为准，包括隔离演练；将本次唯一解析后的库根贯穿所有读写，不能又回写默认库。
- 规范数据独立于本 Skill 保存。使用 Skill 不代表授权修改 Skill 自身、AGENTS、历史规则目录、项目文件或远程内容。
- 只处理跨项目稳定的代码质量要求。技术栈、部署、数据库访问与 ORM、具体模块和业务数据边界属于项目；需求文档、进度、测试执行流程和交接属于需求开发。
- 沿用有效协作与授权约定，避免复制一套重复正文。不把历史文件、讨论中的指令或现有代码写法自动提升为生效规则。

## 读取与处理

1. 读取 [确认清单](references/checklist.md) 和库中已有入口、维护记录。首次逐项处理全部公共项；更新先核对清单、依据和适用范围的变化，再处理受影响项。涉及 Go 或 Python 时按需读取 [Go 补充](references/go.md) 或 [Python 补充](references/python.md)，不批量加载所有语言。其他语言可沿八领域推导补充，不把未知惯例写成事实；易变的工具行为核实官方来源。
2. 按 [规范库与维护格式](references/library.md) 区分推荐组合、历史已发布版本、项目固定引用和未发布候选。固定版本继续有效，不用“最新”覆盖；引用缺失或冲突须说明。候选不能解释为用户批准。
3. 每个适用项形成 `形成规则`、`沿用/默认`、`交给项目/实现`、`不适用` 中一个结论，并记录理由、依据和开放空间。未处理或存在实质冲突的项标为 `待决`，不得计入完成。未启用语言只说明未启用，不生成其全表或文件。
4. 普通选择采用有依据的推荐，记录为 AI 自主决定。只将影响目标、兼容承诺、硬约束且无法合理判断的取舍集中交给用户。先给推荐和影响，不抛整张问卷。硬约束不能静默放宽；可在旧规则内完成的工作继续，冲突影响的组合保留旧版本。
5. 检查候选规则的复用范围、可执行性、依据、重复、冲突及过度约束。能约束结果与责任就不固定机制。属于项目的诉求说明归属，不写入项目，也不伪装为“全局默认架构”。
6. 正文保留强度、条件、例外及决定适用性的关键原因。历史取舍进入记录；读正文的开发 AI 不应依赖历史记录才能正确执行。

## 更新与发布

写入前必须读取 [规范库与维护格式](references/library.md) 的增量失效和发布协议。编号用于追踪，不能作为内容未变的证明。

- 新增、修改、删除、拆分、合并条目，以及偏好、依据、范围和前提变化，都要判断旧结论是否失效。公共变化同时检查语言组合。只复查受影响部分，不重问全部问题。
- 无语义变化且无需新增记录时保持无写入；仅依据或清单记录变化不增加规则版本。清单、公共和语言版本独立。
- 已发布文件不原地改写。先准备候选及记录，检查覆盖、语义、组合和引用，再原子替换入口。未登记候选不是已发布版本。
- 用户扩展保存在库内，不因更新 Skill 覆盖。遇到未完成候选，核对实际文件和依据后恢复；不自动发布或覆盖用户数据。

## 结果与接续

简短说明范围、实际变更、重要自主决定、待决项和验证边界。区分清单覆盖、规范有效与项目代码合规；本 Skill 不执行项目代码验收。

后续项目流程选择明确推荐组合，在项目内固定公共与适用语言版本，并要求开发 AI 实际读取。具体化默认建议不等于可以放宽硬约束。Markdown 链接不保证加载；跨机器缺少库时报告所缺版本，不忽略或擅自替换。

交互参考 [对话示例](references/examples.md)。维护或验收 Skill 时使用 [行为验收方法](references/validation.md)，日常生成不必加载验收材料。
