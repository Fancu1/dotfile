# 全局开发规范

替用户把大致偏好转成可直接执行的开发规则。默认先给可用成品，让用户通过成品反馈调整；不要让用户先学会编写规范或逐项回答清单。规范既要有具体代码写法，也要有设计判断依据，不能只写“清楚、合理、符合惯例”。

## 入口与范围

- 自然语言识别生成、局部更新、检查或讨论。明确生成/更新授权本地写入；讨论和检查只读。用户主动要求讨论时围绕具体草案讨论，不立即落盘。
- 默认输出根为 `~/.config/ai-dev-standards/`；用户指定路径时只使用该根，包括测试。不修改全局或项目 AGENTS、其他 Skill、项目代码或远程内容。
- 只维护当前正文：`common.md` 和 `languages/<language>.md`。不生成版本号、历史版本、INDEX、推荐组合、发布机制、逐项决策台账或项目副本。详见 [文件组织与更新](references/library.md)。
- 公共规范负责跨语言代码质量，语言规范负责具体命名、方法、类型、错误处理等写法。技术栈、部署、数据库访问与 ORM、模块及业务数据边界属于项目；需求方案、进度、文档格式和测试执行流程属于需求流程。

## 根据偏好直接生成

1. 读取用户当前请求、当前对话中已确定的偏好，以及目标目录内已有正文。明确的新要求优先于旧默认；保留未涉及的用户约定。不从当前代码的偶然写法、历史草稿或不明来源文件推断用户已确认。
2. 用户偏好模糊时主动转译：容易读 → 业务命名和清楚控制流；写法一致 → 具体命名与调用约定；不过度设计 → 直接实现优先、按真实需要引入接口；必要注释 → 明确注释语言、位置、内容和例外。普通细节采用成熟默认，不把每项取舍交还用户。
3. 首次生成读取 [公共检查清单](references/checklist.md)、[公共成品样例](assets/common.md)，以及本次语言的补充。Go 读取 [Go 补充](references/go.md) 和 [Go 成品样例](assets/go.md)；Python 读取 [Python 补充](references/python.md)。不加载或生成无关语言。其他语言参照同等具体程度，必要时核实官方语言资料，不机械移植 Go 写法。
4. 样例是用户已认可的成品粒度与默认风格。偏好匹配时直接复用正文，仅做必要调整和清单查漏，不必每次重新撰写。逐条保留适用要求的含义、关键前提和例外；不要把样例摘要化，或仅为“更严格”增加限制。根据当前请求修改，不照抄示例业务契约。样例中的普通默认不意味着本次调用者逐条确认过。
5. 内部逐项检查覆盖。结论可以是已写规则、沿用规则/采用默认、属于项目或实现、不适用；不必逐项询问、向用户展示或落盘。清单用于发现遗漏，不能成为正文提纲、规则数量配额或问卷。
6. 只有缺少会实质改变产出的必要信息，或存在无法由请求消解的真实硬约束冲突时，集中询问并给推荐；普通风格选择先生成。用户未指定语言且无上下文依据时，可先完成通用部分，再询问要补充的语言。未决冲突不混入有效正文，不通过放宽要求制造完成。

## 写成开发 Agent 可以执行的正文

- 命名、格式、注释等可统一的要求写具体：形式、语义和必要例子。例如变量大小写、缩写、布尔及集合名称、函数动词、接收者名称、导出 API 注释。
- 需要权衡的要求给默认做法、触发条件及例外。例如何时提取接口、相似代码是否应合并，不能只要求“适度抽象”。
- 容易误解的边界给短例子，例如缓存失败转查数据源与数据源失败伪装空结果的区别。不要求每条填“强度/条件/依据/例外”表格。
- 必须可从实现或行为判断是否遵守。“明确生命周期”要落到管理者、退出条件、失败观察；不是要求每次开发额外写证明文档。
- 正文保留适用范围、强度及决定适用边界的原因。直接用“必须/不得”和“默认/优先”区分，不把推荐写成唯一合法机制。
- 公共和语言内容互补，不重复整段原则。按开发阅读主题组织，默认每种语言一份完整文件；不按检查项拆文件。不要固定行数、字数或额外测试配额。
- 不让正文充斥确认状态、来源标签、讨论经过或“此项交给项目”的占位段落。少数重要默认在交付回复中说明，不称为用户逐项确认。

## 局部维护与交付

更新前读取 [文件组织与更新](references/library.md)。检查当前清单的相关含义与现有正文，新增或改变的角度不能因旧编号存在而略过；不要求保存清单快照。用户扩展已经写入正文的应保留，不能用样例覆盖。公共变化应检查现有语言正文的关联影响。

只改本次相关条款；未变化的文件不重写，同一请求已经满足时不产生写入。不在局部更新时顺手全面补齐或美化其他部分；发现其他遗漏可简短报告。只读检查不更新文件。

首次生成提供实际正文链接，简述重要默认，并给出项目通过当前绝对路径要求开发前实际读取的用法，不自行修改项目。局部更新只说明实际差异和必要未决项；无变化时简短说明已满足，不重复接入教程或检查表。用户主动询问接入时再展开。全局正文更新后，项目下次读取即使用当前内容。

交互尺度参照 [对话示例](references/examples.md)。只有用户明确要求修改或验证本 Skill 时，才读取 [验证方法](references/validation.md)。普通生成、更新、检查规范不得读取此验收材料或执行其中流程。
