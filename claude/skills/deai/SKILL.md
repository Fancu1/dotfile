# DeAI — 去 AI 味

检测中文技术文本中的 AI 生成痕迹，标注问题并改写为自然的人类文本。

**适用场景：** 简历、项目描述、技术文档、自我介绍
**不适用：** 学术论文、英文文本、文学创作

## 触发方式

- `/deai` 或 `/deai 审查` — 审查模式（默认）：扫描文本，标注 AI 痕迹
- `/deai 改写` — 改写模式：审查 + 改写为人类风格
- `/deai 改写 @参考文件` — 带 voice calibration 的改写

## 模式 1: 审查

### 流程

1. **加载模式库**：读取同目录下的 `patterns.md`
2. **确定目标文本**：用户粘贴的文本、指定的文件路径、或对话上下文中的文本
3. **逐句扫描**：对每个句子/bullet 检查是否命中模式库中的模式
4. **输出审查报告**

### 扫描规则

按四层顺序扫描，每层独立标注：

- **P1 词汇层**：逐词检查是否命中高频词表
- **P2 句式层**：检查句子结构是否匹配 AI 句式模板
- **P3 篇章层**：检查 bullet 间的关系（是否塞了多件事、是否长度均匀、描述段是否塞了架构）
- **P4 修辞层**：检查数据可追问性、重复强调、意义膨胀

### 输出格式

```markdown
## 审查结果

**目标文本：** [文件名或"用户输入"]

### [P编号 模式名]
> 原文引用
具体问题 + 修复建议（一句话）

### [P编号 模式名]
> 原文引用
具体问题 + 修复建议（一句话）

...

## 统计
- 扫描：N 句
- 命中：M 处
  - 词汇层 P1：X 处
  - 句式层 P2：Y 处
  - 篇章层 P3：Z 处
  - 修辞层 P4：W 处
- AI 浓度：高（>10 处）/ 中（5-10 处）/ 低（<5 处）
```

### 注意事项

- 同一句话可能命中多个模式，全部标注
- 不标注没有问题的句子，只标注有问题的
- 修复建议要具体到"删掉"、"换成 X"、"拆成两条"，不说"优化表述"这种空话
- 如果全文 AI 浓度低（<3 处），直接说"基本没问题"，不硬找

## 模式 2: 改写

### 流程

1. **内部审查**：先执行审查流程，得到问题列表（不输出给用户）
2. **Voice Calibration**（如果用户提供了参考文本）：
   - 读取参考文本
   - 提取风格特征：句长分布、动词选择、bullet 结构、信息密度
   - 改写时匹配这些特征
3. **逐条改写**，遵循改写原则
4. **输出改写结果 + 变更说明**

### 改写原则

这些原则来自对"写得好的人类技术文本"的共性总结：

1. **一条 bullet 一件事**：能拆就拆，拆完每条要有自己的动词和数据
2. **只说 what + 数据**：不在 bullet 里解释 how 和 why，那是面试时口头展开的
3. **具体动词开头**：主导、负责、设计、搭建、维护、推动——不用"实现...机制"、"构建...体系"
4. **砍总结句**：说完数据就收，不加"确保 XXX"、"提升 XXX"
5. **砍包装词**：删掉不影响语义的修饰词
6. **数据要经得起追问**：写的每个数字都要能回答"怎么算的"
7. **描述段只讲角色范围**：架构和技术细节放 bullet

### 输出格式

```markdown
## 改写结果

### 改写后全文

[完整的改写后文本]

### 变更说明

| # | 原文（关键部分） | 改为 | 原因 |
|---|----------------|------|------|
| 1 | ... | ... | P1.1 包装词 |
| 2 | ... | ... | P3.1 拆 bullet |
| ... | | | |
```

### 改写禁忌

- **不加信息**：只删减和重组，不编造原文没有的内容
- **不丢信息**：关键数据和事实必须保留，只是换表述
- **不过度口语化**：简历是书面文本，保持专业但不生硬
- **不引入新的 AI 模式**：改写后的文本不能命中 patterns.md 里的任何模式
- **不动没问题的句子**：审查没标注的句子原样保留

## Voice Calibration

用户可以提供参考文本（文件路径或粘贴），skill 会提取以下特征用于指导改写：

- **句长分布**：参考文本的平均句长、最短/最长句
- **动词偏好**：参考文本常用的开头动词
- **bullet 结构**：参考文本的 bullet 一般多长、一条讲几件事
- **信息密度**：参考文本一个 bullet 平均包含几个数据点

提取完成后，改写时以参考文本的风格为目标，而不是用一个通用的"好文本"标准。

## 模式库维护

模式库在 `patterns.md` 中独立维护。发现新的 AI 模式时：

1. 确认是可复现的模式（不是个例）
2. 归入四层中最合适的一层
3. 按现有格式写入：编号、名称、说明、示例、修复建议
4. 编号规则：P[层号].[序号]，新增只加不改已有编号
