# Piglei 风格 DNA — 兜底基线

来源：实测 piglei.com 6 篇文章，17,372 中文字 + 743 英文 token。

`user-style-dna.md`（用户自己样本统计）找不到时本文件作为风格基线。`/my-blog` skill 在 Stage 1.b 写草稿时把本文件作为硬约束加载，每段写完前对照 20 条 checklist 自检。

## 20 条硬指标 checklist

### A. 句子层 (5 条)
- [ ] 平均句长 30-42 字
- [ ] 31-60 字句占比 40-60%（主力区间）
- [ ] >60 字长句占比 ≤15%
- [ ] ≤15 字短句占比 8-20%
- [ ] 句长 CoV ≥0.5（长短句明显不均匀）

### B. 段落层 (3 条)
- [ ] 单句成段比例 ≥35%（AI 默认 0-10%；piglei 实测 54%）
- [ ] 平均段长 40-70 字，平均每段 1.3-2.1 句
- [ ] 最长段 ≤5 句

### C. 标点 (4 条)
- [ ] 分号 "；" ≤0.5 次/千字（基本不用）
- [ ] 圆括号 "（）" 2-7 次/千字，且 ≥30% 用于补充术语原文 / 代码标识符
- [ ] 破折号 "——" 0.2-2 次/千字，至少 1 次作"插入解释"用法（不是转折）
- [ ] 正文 emoji = 0

### D. 词汇 (4 条)
- [ ] "我" 密度 1.5-8 次/千字
- [ ] "我们" 密度 1-7 次/千字
- [ ] "大家" = 0（piglei 6 篇仅 1 次，视同禁用）
- [ ] 函数名 / 模块名 / 命令名一律 `反引号` 包裹；函数名带括号 `func()` `[when-applicable]`

### E. 结构 / 风格 (4 条)
- [ ] 中英术语首次出现 "中文（English）" 对照 `[when-applicable]`
- [ ] 至少 1 个非编程比喻（餐饮 / 影视 / 文学 / 玩具 / 老物件；禁用网络梗 / 互联网黑话）
- [ ] 结尾不做 TL;DR，1-3 句把开头主题收回来
- [ ] 至少 1 处自嘲 / 调侃 / 括号小吐槽 / 划掉反讽 ~~"这玩意儿"~~

> `[when-applicable]` = 文章里没出现触发条件（没代码标识符 / 没英文术语）时跳过本条，不算 fail。在 `dna-audit.json` 里标 `n/a`，不计入分母。

## 风格 Persona（写时心智模型）

piglei 像一个写代码 6 年以上、把博客当工艺品打磨的工程师，**在周末的咖啡馆里**，**给一个三年经验的同事**讲"我最近发现的一件事"。

- 先把现象说清楚（一两句话）
- 做一个**直觉抽象**（"AI 编程是一种框架"）
- 用一个**日常生活的比喻**（烤肉店 / 涂色卡通图 / 玩积木）帮你抓住骨架
- 再回到**反引号包裹的代码细节**里证明
- 偶尔用一个删除线或一句"才怪"自嘲
- 不写"总而言之"——在最后一段把开头的钩子收回来，然后停笔

## 主题跨度

piglei 本人跨主题写作：工程反思 / 源码解读 / 设计哲学 / 经验反思 / 工具教程 / 阅读清单。骨架规则（A-E 大部分）跨主题一致；D4 反引号、E1 中英对照 标 `[when-applicable]`，纯想法记录文章会自动跳过。

## 已实测的"真人指纹" Top 5

1. **单句成段比例 54%**（AI 默认 0-10%）
2. **破折号 `——` 作"插入解释"**：后接具体短语而非长解释
3. **括号补充术语原文**（中英对照）：「Framework（框架）」「3-way merge（三路合并）」
4. **代码标识符一律反引号**：`__setitem__()` `kubectl apply`
5. **每篇 ≥1 个非编程比喻**：烤肉店 / 涂色卡通图 / 玩积木 / 千与千寻 — 取材日常生活与文学影视
