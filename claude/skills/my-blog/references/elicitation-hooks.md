# Stage 1.a Elicitation Hooks

skill 在 Stage 1.a 主动追问以下 5 个 hook，把零散想法补齐到能写出真东西的密度。"核心观点" + "≥1 个具体锚点"是**硬门槛**，没这两项不进 Stage 1.b。

## 5 个 Hook

### Hook 1: 核心观点（硬门槛）
**问法**：「这篇你最想让读者记住的一句话是？」
- 期望：≤25 字一句话能说清
- 例子：「AI 编程是一种框架」/「Code Review 时常被忽视的 3 件小事」/「我为什么把博客拆成 monorepo」
- 拒绝模式：抽象大词（"AI 的未来"）/ 没观点的题目（"聊聊 X"）→ 追问"具体什么观点？"

### Hook 2: 具体锚点（硬门槛）
**问法**：「这观点你打算用什么具体例子撑住？至少 1 个：经历 / 数字 / 对话 / 引文 / 一段代码 / 一本书一首歌。」
- 期望：可以被原样写进文章的具体材料
- 例子：「上周排查的一个 deadlock，对应的 stacktrace 有 X 行」/「《长日将尽》里 Stevens 临终前的那段话」/「`__setitem__()` 的 patch diff」
- 拒绝模式：「大概是 X 之类的」「类似的有很多」→ 追问"举一个 specific 的"

### Hook 3: 目标读者（可选）
**问法**：「你写给谁看？不填我按文章性质判：技术类 → 3 年经验同事；反思 / 想法记录 → 朋友 / 同事。」
- 默认：LLM 看 Hook 1+2 自动判
- 用户填了：以用户填的为准

### Hook 4: 字数区间（可选）
**问法**：「字数大概多少？极短 500-900 / 短 1200-1800 / 中 2000-3000 / 长 3500-5000。不填我按文章性质自决：纯想法记录偏极短/短，反思偏中，教程 / 设计哲学偏中/长。」
- 默认：LLM 按文章性质判
- 用户填了：以用户填的为准（上下浮动 ≤15%）

### Hook 5: 反例（可选）
**问法**：「这篇不要写成什么样？（可跳过）」
- 用途：明确避坑（"不要写成方法论"、"不要列 N 条 tips"、"不要总结型结尾"）
- 默认：跳过

## 文章性质识别（不在 elicitation 里显式问）

LLM 看 Hook 1+2 自动判：

| 性质 | 信号 |
|---|---|
| 技术 | 锚点含代码 / stacktrace / 工具命令 / 函数名 |
| 反思 | 观点是"我重新认识 X" / "我以前以为 Y，现在 Z" |
| 想法记录 | 观点散漫、锚点是日常对话 / 见闻 |
| 阅读笔记 | 锚点是书 / 文章 / 播客 / 引文 |
| 生活观察 | 锚点是非编程场景的日常事件 |

性质影响：
- `[when-applicable]` 条目是否触发（反引号 / 中英对照）
- 字数默认档
- 目标读者默认

## 拒绝进入 Stage 1.b 的判定

```
如果 Hook 1 缺失 → 拒绝，重问
如果 Hook 2 完全没具体材料（"差不多"、"类似的"）→ 拒绝，重问
否则进 Stage 1.b
```

## 01-ideas.md 输出格式

```markdown
# Ideas — <slug>

**生成时间**：YYYY-MM-DDTHH:MM:SS+08:00
**核心观点**：<Hook 1 答案>
**文章性质**：<LLM 判定结果>
**目标读者**：<Hook 3 答案 / LLM 默认>
**字数档**：<Hook 4 答案 / LLM 默认>
**反例**：<Hook 5 答案 / [跳过]>

## 用户原始输入
<复制用户最初给的零散想法，原样保留>

## 锚点清单
1. <Hook 2 答案 1>
2. <Hook 2 答案 2 if any>
...

## 我（LLM）准备怎么写
（≤200 字大致路线：从哪个锚点切入、中间用什么比喻、结尾怎么收）
```
