# Soul-Loss Guard — 反"中性说明书"

终稿补丁（Stage 2.a）应用 Top N patches 后，跑本检查对比 `patch-version` 和 `02-draft.md`。**命中 ≥3 条 → 全部回滚到 02-draft.md**，不接受补丁。

## 7 条回滚判定

- [ ] **句长节奏被压平**：句长 CoV 比草稿下降 >20%
- [ ] **段落节奏被均化**：单句段比例从草稿的 X% 降到 <30%
- [ ] **形容词被中性化**：草稿里"有偏见的形容词"被改成中性
  - 例：「愚蠢的设计」→「不太合适的设计」
  - 例：「写得真烂」→「实现质量有待提升」
- [ ] **具体锚点被抽象化或被删**：草稿里的数字 / 引文 / 经历 / 代码片段在终稿里被改成抽象描述或直接删
  - 例：「上周排查的 deadlock，stacktrace 有 47 行」→「最近遇到的一个并发问题」
- [ ] **比喻被删**：草稿里的非编程比喻（烤肉店 / 涂色卡通图 等）在终稿里消失或被替换成抽象描述
- [ ] **自嘲被删**：草稿里的 ~~划掉反讽~~ / 括号小吐槽（才怪）/ 戏谑词被改正
- [ ] **结尾被套话化**：草稿结尾的"开放陈述 / 一句祝福 / 反问"被换成"通过本文，可以看到..." / "总的来说..." 类套话

## 判定主体

由 **LLM 现场对比**草稿 vs 补丁版做 yes/no 判定（**不写自动化脚本**）。每条命中给出具体 evidence（草稿 line X "原句" → 补丁 line Y "改后"）。

## 回滚行为

```
命中 ≥3 条：
  - 03-final.md = 02-draft.md 副本（不应用任何 patch）
  - 在 03-final.md 末尾附 audit 报告（HTML 注释包裹）：
    <!--
    Soul-Loss Guard 触发回滚
    命中条目：[X, Y, Z]
    建议手动改这几个 AI 痕迹位置：
      - line A: "<原句>" — P1 红线词 "总而言之"
      - line B: "<原句>" — P1 红线词 "让我们一起"
      ...（列出所有 P1 优先级的 deai patch 候选）
    -->

命中 1-2 条：
  - 03-final.md = 接受补丁
  - 在 03-final.md 末尾附 audit 报告：
    <!--
    Soul-Loss Guard 警告（未回滚，请人工确认）
    被改动的灵魂位：
      - line A: 草稿 "<原句>" → 终稿 "<改后>"（命中"形容词中性化"）
      ...
    -->

命中 0 条：
  - 03-final.md = 接受补丁
  - 在 03-final.md 末尾附 audit 报告：
    <!-- Soul-Loss Guard 通过，无灵魂位改动 -->
```

## 设计原则

- 优先保灵魂：deai 是 AI 痕迹清除器，不是风格仲裁者。**宁可保留一点 AI 痕迹也不要变中性说明书**
- 不重试：补丁回滚后**不再重写**，建议用户手动改
- 完全透明：每条命中必须给具体 line + 原句 + 改后句，让用户能验证判定
