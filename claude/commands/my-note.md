description: 追加 / 管理跨项目笔记 — 自然语言（无子命令）
---

维护 `~/wpx/my/note.md`，装疑惑 / 待办 / 灵感。**接受自然语言输入，不用子命令**。

## 输入解析

### 无参数

1. 读 `~/wpx/my/note.md`
2. 按类型分组列出：
   - [疑惑] 状态 = 待消化
   - [待办] 状态 = 待做
   - [灵感] 最近 7 天
   - 最近 7 天的已掌握 / 已做（轻量展示，让候选人有"在推进"的感觉）
3. 问："加新的、改状态、还是看？"

### 带参数（`/my-note <自然语言>`）

判断意图：

**a. 加 note（默认意图）**

按用词推断类型：
- **疑惑**：不懂 / 不熟 / 困惑 / X 是什么 / X vs Y / 为啥 / 没搞清
- **待办**：要做 / TODO / 提醒 / 别忘 / 得 / 应该 / 计划
- **灵感**：想到 / 灵感 / 点子 / 觉得可以 / 假如 / 突然
- **完全猜不出** → 反问"这条算 [疑惑 / 待办 / 灵感] 哪类？"

**b. 改状态**

线索词：搞懂了 / 弄明白了 / 做完了 / 完成了 / 不做了 / 算了 / 弃 / 已掌握
→ 模糊匹配 note.md 条目，复述确认，改状态为 已掌握 / 已做 / 已弃

**c. 看**

线索词：看 / 列 / 查 / 哪些 / 现在 / 我有什么
→ 同无参数

**d. 歧义** → 反问"这条想做什么？加 / 改状态 / 看？"

## 执行逻辑

### 加入

1. 推断类型 + 取标题（输入第一句或最显眼短语；判断不清就反问"给个简短标题？"）
2. 准备条目（默认状态：疑惑 → 待消化、待办 → 待做、灵感 → —）：
   ```markdown
   ## YYYY-MM-DD [类型]：主题
   （内容 / 用户原话）

   - 状态：默认值
   - 来源 / 关联项目：留空或用户提供
   ```
3. **预览** 给候选人："准备加这条：[展示]，确认？"
4. 候选人确认 → 在 `---` 分隔符之后**顶部插入**（保持倒序）
5. 反馈："已加 [类型]：[主题]，note 共 N 条待处理。"

### 改状态

1. 模糊匹配条目（按标题 / 内容关键词）：
   - 1 个 → 直接用
   - 多个 → 列候选让候选人选
   - 0 个 → 告知找不到，让候选人用"看"先确认
2. 复述："把 [类型]：[主题] 改为 [新状态]，对吗？"
3. Edit 改对应条目的「状态」行
4. 反馈："已改：[标题] → [新状态]。"

### 看

按类型分组打印（重点：待消化 / 待做 / 最近灵感）。完整列表用户自己开文件看。

## 边界

- 用户给一大段（多行）笔记 → 整段存内容，标题取第一行或反问
- 类型自相矛盾（"我不懂 X 但要做 X"）→ 反问哪类为主
- 状态修改匹配 0 条 → 告知，不自作主张创建新条目
- 主题已存在（同名）→ 提示"已有同名条目 [日期]，是更新还是另存？"
- 来源 / 关联项目用户没说就留空，**不要替他编**
