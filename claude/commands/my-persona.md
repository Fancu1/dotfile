维护 `~/.claude/persona.md`。**接受自然语言输入，不用子命令**。

## 输入解析

### 无参数

1. 读 `~/.claude/persona.md`
2. 判断状态：
   - **空骨架**（所有 section 都是"（待填）"）→ 进入**首次引导流程**
   - **部分填**（有些 section 有内容，有些还是"（待填）"）→ 展示现状 + 问："还没填的有 [列出]。想继续填、还是改已经填的？"
   - **全填** → 展示现状 + 问："想改哪段？（身份 / 沟通偏好 / 核心原则 / 技术栈 / 工具链 / 反模式 / 测试 / 工作态度）"

### 带参数（`/my-persona <自然语言>`）

解析意图：

- **重置**：`重置` / `清空` / `删掉所有` → 二次确认 → 清回空骨架（所有 section 回到"（待填）"）
- **指定段改**：`改沟通偏好` / `沟通偏好那段加一条` → 定位到该段，展示当前内容，问"改什么？"
- **具体内容**：`我讨厌 TDD` / `我最近在学 Rust` → 判断属于哪段（测试偏好 / 技术栈），展示该段，问"加进去？"确认后合并
- **歧义** → 复述理解让用户确认："这条像是 [段名] 的内容，对吗？"

## 首次引导流程

按顺序问八个维度。**一次一个问题，等答复再问下一个**。用户可随时说"跳过"，跳过的段保留"（待填）"。

### 1. 身份
"你的职业定位是？"
追问：工作年限、核心强项、当前在转型或学习什么

### 2. 沟通偏好
"你和 AI 聊技术，喜欢什么风格？"
追问：语言、节奏、反感的表达方式（比如百科式开头）、是否希望被直接反驳而不是迎合

### 3. 核心原则
"改生产代码时，你不可妥协的 2-3 条原则是什么？"

### 4. 技术栈
"主力语言 / 框架是什么？"
追问：基础设施（DB / 中间件 / 编排）、学习中的、不熟的领域

### 5. 工具链偏好
"有没有强偏好的工具？"
追问：Git（GitHub / GitLab CLI）、搜索、JSON、调试、venv、浏览器自动化

### 6. 反模式（禁区）
"有没有绝对不允许的实现方式？"
（示例可启发：`--no-verify`、`any` 逃逸、silent 吞错、breadcrumb 注释）

### 7. 测试偏好
"测试怎么看？集成 vs 单元比例？mock 的态度？"

### 8. 工作态度
"探索期和生产期你工作风格有区别吗？对 hype 和 buzzword 的态度？"

## 执行逻辑

### 加 / 改单段

1. 读当前段内容
2. 展示给用户看
3. 用户描述改动（追加 / 替换 / 删除某条）
4. **预览合并后的结果**：
   ```
   改完这段会变成：
   
   [新内容]
   
   确认写入？
   ```
5. 用户确认后用 Edit 更新 persona.md 对应段

### 清空

二次确认："确定清空整个 persona.md？会保留 section 骨架。" 两次 y 才执行。

## 边界

- 用户答"嗯，差不多吧" → 让他自己说具体版本，**不要 AI 替他编**
- 用户跑题到 goals 级内容（"我今年要拿 AI 平台 offer"）→ 问"这条像是 goals，放 persona 还是 goals？"
- 首次引导总时长控制：≤ 15-20 分钟；用户疲劳就暂停，说"改天继续"
- **每次写入前完整预览全文**让用户过一遍再落盘
- 所有改动直接写进 `~/.claude/persona.md`，不需要独立确认机制（预览 + 确认已足够）
